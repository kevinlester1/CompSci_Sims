B4.1.1 Properties and Purpose of ADTs

An Abstract Data Type (ADT) is a logical description of how we view the data and the operations that are allowed on it, completely independent of how it will be implemented in a specific programming language.

The "What" (Logical Level)

ADTs provide a high-level description. They specify what data is stored and what operations can be performed.

  • Defines operations (e.g., insert, delete, search).
  • Hides complex implementation details (Abstraction).
  • Allows developers to focus on problem-solving rather than memory management.

The "How" (Implementation Level)

Data Structures are the actual concrete implementation of an ADT in code.

  • Involves writing the actual algorithms for the operations.
  • Requires understanding of memory (e.g., contiguous vs. non-contiguous).
  • A single ADT (like a List) can be implemented in multiple ways (Array or Linked List).

Conceptual & Factual Knowledge Check

Q: What is the primary difference between an ADT and a Data Structure?

Hover to reveal answer... An ADT is the theoretical concept outlining what operations are possible (e.g., a "List"). A Data Structure is the concrete implementation in code indicating how it exists in memory (e.g., a "Linked List" or "Static Array").

Q: Why is "Information Hiding" an important property of an ADT?

Hover to reveal answer... It allows the programmer to use the ADT without needing to understand the complex code underneath. If the internal implementation changes (e.g., upgrading for efficiency), the rest of the program using the ADT does not need to be rewritten.

Comparisons

Vs. Static Arrays: Lists dynamically resize and allow O(1) insertions/deletions (once found). Arrays have fixed size but allow O(1) random access.
Vs. Stacks: Stacks are strictly LIFO (Last In, First Out). Linked Lists can insert/delete anywhere.
Vs. Trees (BST): Trees allow O(log n) searching (if balanced). Linked Lists require O(n) linear searching.

Knowledge Check

Q: Why might a Doubly Linked List use more memory?

Hover for answer... Every node must store an additional pointer addressing the previous node, increasing memory overhead.

Q: What happens if a Circular List algorithm doesn't check for the starting node?

Hover for answer... It will result in an infinite loop during traversal, as there is no NULL terminator.

Real-World Applications

How are Linked Lists used in modern software development?

Music Player Playlist

Type Used: Doubly Linked List

In a music player, you need to navigate to the 'Next' track and the 'Previous' track seamlessly. A Doubly Linked List stores song objects as nodes, where next points to the upcoming song and prev points to the last played song.

Web Browser History

Type Used: Doubly Linked List

When you hit the 'Back' and 'Forward' buttons on a browser, you are traversing a Doubly Linked List of URLs. Each new page visited is inserted as a new node, updating the current pointer.

Undo/Redo Mechanisms

Type Used: Doubly Linked List

Software like Word Processors or Image Editors track state changes. An Undo moves the pointer prev to the previous state, while Redo moves it next. If a new action is taken after an undo, the forward chain is severed and replaced.

CPU Task Scheduling

Type Used: Circular Linked List

In Operating Systems (like Windows or Linux), the CPU uses Round-Robin scheduling to allocate time slices to running applications. A Circular List allows the OS to continuously loop through open tasks indefinitely.

Python Implementations

Singly Linked List

The fundamental implementation. Notice how deletion requires keeping track of a prev pointer manually during traversal to bridge the gap when removing a node.

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

class SinglyLinkedList:
    def __init__(self):
        self.head = None
        
    def insert(self, data):
        new_node = Node(data)
        new_node.next = self.head
        self.head = new_node
        
    def search(self, key):
        current = self.head
        while current is not None:
            if current.data == key:
                return True
            current = current.next
        return False
        
    def delete(self, key):
        current = self.head
        prev = None
        
        while current is not None:
            if current.data == key:
                if prev is None: # Deleting head
                    self.head = current.next
                else:            # Bridge the gap
                    prev.next = current.next
                return True
            prev = current
            current = current.next
        return False

Doubly Linked List

Nodes now have a prev property. Deletion is simpler conceptually (no need to track a separate prev variable in the loop), but requires updating two pointers (next and prev) to securely bridge gaps.

class DNode:
    def __init__(self, data):
        self.data = data
        self.next = None
        self.prev = None

class DoublyLinkedList:
    def __init__(self):
        self.head = None
        
    def insert(self, data):
        new_node = DNode(data)
        if self.head is not None:
            self.head.prev = new_node
        new_node.next = self.head
        self.head = new_node
        
    def delete(self, key):
        current = self.head
        while current is not None:
            if current.data == key:
                if current.prev is not None:
                    current.prev.next = current.next
                else:
                    self.head = current.next # Was head
                    
                if current.next is not None:
                    current.next.prev = current.prev
                return True
            current = current.next
        return False

2. Algorithmic Design

Before coding, determine which Abstract Data Type is most appropriate. While a standard Queue (FIFO) works for regular patients, the need to insert at the front violates strict Queue rules. A Linked List allows O(1) insertion at the head (for critical patients) and O(1) insertion at the tail (for standard patients, if a tail pointer is maintained).
